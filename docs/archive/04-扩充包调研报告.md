## 0. 执行摘要与行动建议

### 0.1 做新包前必须先修的两个代码问题（已核实）

1. **包校验误拒 4 个中文算法**：`StylePack.cs:727` 的 `AlgorithmCount = (int)KnownAlgorithm.StripCombiningMarks`（=14），但 `KnownAlgorithm` 枚举有 19 个成员（`TransformStep.cs:42-63`）。`ValidateStep` 的上限检查（`StylePack.cs:272`）会把 `simplified-to-traditional` / `traditional-to-simplified` / `pinyin` / `pinyin-abbr` 拒为"未知算法"——尽管 `StylePackJson.cs` 的 kebab 转换器本就支持这四个名字（意图是让包可用，属加中文算法时忘更新校验常量）。修法：`AlgorithmCount` 改为最后一个成员 `PinyinAbbr`，并补包内使用这四算法的测试。
2. **双线体 R 码点笔误**：`LatinMaps.cs:53` 的 `DoubleStruck` 表 `['R'] = "\u211C"`（ℜ，Script Capital R），标准双线体 R 是 **U+211D**（ℝ）。42 行 fraktur 用 `\u211C` 是对的（那是 Fraktur R 的 Letterlike 洞位），53 行系复制笔误。

另有一项文档债：`StylePack.cs:7` 注释"格式见 docs 样式包规范"是虚指——规范实际由 `docs/sample-pack.json` + README + 代码校验层承载，建议沉淀为真正的 `docs/样式包规范.md`。

**谨慎/不做**：竖排名（spacing 换行——平台过滤风险高，只作彩蛋包）；真·汉字头顶自动注音（技术上不可行，纯文本无 GPOS 控制）；Wingdings/私用区、Regional Indicator 旗帜（不可控显示）；中文镜像字大全（无 Unicode 基础，至多 20-50 字整活并入他包）。

### 0.3 分发机制建议（要点，详见第 5 章）

主路径：**独立 GitHub 仓库做包索引（index.json）+ 应用内"获取更多包"拉 raw 清单 + jsDelivr 镜像应对国内访问**——微软 CmdPal-Extensions 画廊与 Obsidian community 索引的同款模式，与现有"落盘即生效/同包名覆盖"机制零冲突，约一周内可落地。配套：JSON Schema 发布（`$schema` 头获得 IDE 自动校验）、包名"作者前缀.包名"命名空间防覆盖劫持、CI 机器审 + 单人合并、`featured` 精选位。官方包策略：仅保留 1 个核心包随程序内嵌，其余官方包全部走 registry（避免体积膨胀）。

### 3.2 逐字装饰（wrapEach）

点系 ·˙•⋅﹒・；星系 ⋆✧✦✩˚；花系 ❀✿✾；线帽 ⌒¯˘；日系 ヽヾ々ゝ丶；上标小字母 ˢᵗᵒᵖᵉʳ（英文专用）。风险低，注意长度翻倍（微信昵称按码元计长）。

### 3.3 字间分隔（spacing，≤4 码元）

中点族 ·•・⋅‧；直线族 ─━═┄┅┈⋯…；波浪族 ～〰⌒﹏≈；日式点线 ヽ丶〆ゝ；混合 `⋆·˚`（多字符注意 4 码元截断）。极低风险；～ U+FF5E 中文生态最通用。

### 3.4 组合附加符号（appendMark，U+0300–036F）

- 上方：加点 U+0307/0308、上圈 U+030A、帽子 U+0302/0306/030C/0303、上划线 U+0305/033F、上竖线 U+030D/030E、锯齿 U+035B、上箭头 U+0350
- 下方：加点 U+0323（zalgo 座上宾）/0324、下圈 U+0325、下划线 U+0332/0333/0331、下竖线 U+0329/0348、下波浪 U+0330、软音符 U+0327
- 穿字/glitch：**删除线 U+0335/0336**、斜杠 U+0337/**0338**（经典禁止效果）、波浪穿字 U+0334
- 小字母叠加 U+0363–036F（ͣ ͤ ͥ ͦ…="字头顶小字母"）
- **黑名单**：U+034F（grapheme joiner，不可见纯害）；U+0340/0341/0343/0344（废弃等价字符，NFC 折叠消失）；U+035C–0362（双字符连接符，会把相邻字焊在一起，CJK 极易错位）
- **Zalgo 层数经验**：1–3 可读安全（昵称建议 ≤2）；4–6 撑高行框；10+ 破坏界面；FancyText 上限 8 偏激进，**包内控制在 2–4 层**
- **汉字叠加渲染**：手机端（Noto 栈）多数能叠上（微信加点玩法流行的原因）；Windows 桌面微信/QQ 与低端安卓常见豆腐/◌/断开——appendMark 包以英文数字为主打，汉字样式 UI 标注"手机端最佳"
- **勘误**：竖线穿字正确码点是 **U+20D2**（U+20D7 是上方右箭头）；圈/框包字是 U+20DD/20DE——这些在 U+20D0–20FF 块，**超出当前 appendMark 白名单**，如需"穿字/套圈"效果须扩白名单或退化用 0335/0336/0338

### 3.5 分隔线/边框素材

横线 ─━═┄┅┈┉；圆角框 ╭╮╰╯ U+256D–2570（`╭────╮` 注意单侧 8 码元=4 个 ─，建议 ━═█ 粗重单字符或 `╭─╮` 短框）；双线框 ╔╗╚╝═║；竖线 │┃║┆┇；块条渐变 ▏▎▍▌▋▊▉█；波形条 ▁▂▃▄▅▆▇█；括号框 【】〖〗「」『』《》〈〉；角标 ⌜⌝⌞⌟、❝❞。风险极低。

### 3.6 兼容性总表

- Windows 覆盖好：星花几何框线（Segoe UI Symbol）；꧁꧂（Javanese Text 8.1+）；藏文（Himalaya）；ᝰ（Segoe UI Historic 10+）；꒰꒱（Yi Bai）；印度系（Nirmala UI 8+）；ᥫ（Tai Le 8.1+）；ᡣ（Mongolian Baiti）
- Windows tofu 高风险（不用）：᭄（巴厘）、𖥔（巴蒙）、𐭩（帕提亚）、ꕤ（Vai）、࣪（阿拉伯扩展旧系统）
- Emoji 化：安全（永不）♡❥★☆✦✧✿❀◆◇☽☾♛♕✮⋆；会变 ❤（手机端实际）、♥+FE0F、☀+FE0F、❣+FE0F、♟、星座 ♌ 系——**装饰选型一律优先 ♡ 系**

## 4. 中文向玩法调研

### 4.1 竞品与平台玩法

- **输入法花漾字**：搜狗 2015 首推（40 种动态修饰：帽子/翅膀/花草/注音/加点——**"注音"实为固定组合符的假注音**）；百度输入法花漾文/特技字；讯飞有"字后括注拼音"形态（纯数据可复刻）与装饰特效
- **平台昵称流行玩法**：爪哇文翅膀框 `꧁༺名༻꧂`/`ℳঞᩚ最ꦿ初້໌ᮨ꧔ꦿ᭄`（25+ 变体生成器）；菊花文/加点字（2011 至今，U+0489 ҉ 为主，另有热出汗/环绕波浪变体）；拼音声调昵称（`xiǎo míng`，抖音"头顶加点"网名）；竖排昵称（微信/抖音/王者，靠小程序生成粘贴，部分平台过滤换行）；生僻字取名风（2023-24 春晚"龙行龘龘"带火，约 6000 万人名字含生僻字）；卖萌后缀/拼音缩写黑话（xswl/dbq/zqsg）；佛系文艺签名模板（`── 愿岁月温柔 ࿐ 不争不抢 ──`，个签站 12 大类 10 万+条）
- **倒字/镜像现状**：所有中文颠倒生成器都只支持拉丁——中文侧是空白
- **火星文资源**：商业工具原理=常用字↔火星文映射表；**开源实测**：Niefee/textConversion 的 a.js 含 3 张等长对齐表、每张 3815 字（GB2312 一级字库顺序，简体原文+火星文×2 变体）——业界标准规模约 3800 条/表；另有 wangjianlewo/Convertor、gurecn/YuyanIme（3.6k star，Rime 火星文方案）等

### 4.2 可行玩法评估（结论）

| 玩法 | 结论 |
|---|---|
| 菊花文/加点/假注音 | appendMark 现成，中英通吃；桌面端错位需标注；★★★★★ |
| 真·自动注音（汉字上动态标拼音） | **不可行**：多字母无法经组合符叠上、CJK 基字 GPOS 多数字体不支持；放弃 |
| 字后括注拼音（讯飞风） | mapReplace 可行；**6 字母音节带括号=9 码元超限**→空格式 `状 zhuàng`=8 恰好/声调数字式 `状4`=3；字频 top2000 或拆双样式；多音字人工校 |
| 注音符号 ㄅㄆㄇ 括注 | `字(ㄓㄨㄤˋ)` 最长=8 码元恰好达标；Unihan kBopomofo 程序化导出 |
| 火星文 | 3815 条>2048 上限→拆"常用/次常用"两样式或按频率取 2000；开源表 License 不明建议自建校改 |
| 生僻叠字 | 善→叒/火→焱/水→淼/龙→龘/金→鑫 小表，数十条无压力，BMP 优先 |
| 翅膀/花边框 | wrapString 25 套预设；桌面端爪哇文可能窄方块，注明"手机端最佳" |
| 竖排 | spacing=换行（需确认 op 允许转义换行）；平台过滤风险高，定位进阶彩蛋 |
| 中文倒字 | 无 Unicode 基础无现成数据，至多 100–300 字人工形近表整活（干↔士/由↔甲） |
| 颜文字 | wrapString 尾缀+高频词 mapReplace（哈哈→(๑˃̵ᴗ˂̵)）；数据集：ekohurt 62k/kaomoji-collection 41k/kaomoji-json 4k |
| 拼音声调纯拼音风 | `小→xiǎo` 最长 7 码元达标；预组合带调字母全平台覆盖 |
| 缩写黑话 | 条目极少纯 ASCII，无压力 |

### 4.3 候选包（7 个）

①菊花文·复古加点 ★★★★★ ②讯飞风·拼音括注 ★★★★☆ ③ㄅㄆㄇ 注音台湾风 ★★★★☆ ④火星文·非主流复活 ★★★★★ ⑤生僻叠字·叒龘风 ★★★★☆ ⑥花边翅膀·爪哇文 ★★★★☆ ⑦颜文字·情绪后缀 ★★★★★；⑧竖排名 ★★★☆☆（谨慎项）。

**关键结论**：所有 2048 条上限场景靠"字频截断或拆双样式"解决；8 码元值上限唯一卡点是 6 字母拼音带括号（9 码元），用注音/空格/数字声调式规避——全部纯数据方案，无需改引擎。

## 5. 生态与分发机制调研

### 5.1 先例盘点（要点）

| 项目 | 机制 | 借鉴点 |
|---|---|---|
| Rime/東風破 plum | 纯数据 YAML 仓库 + bash 安装器；README 人工精选索引；支持 `user/repo@branch` 引第三方；Weasel 内置"获取更多方案"按钮 | **最同构先例**：预设内嵌+扩展走仓库；ZIP 手动落盘兜底 |
| 微软 CmdPal-Extensions | 社区画廊仓库：PR 加一个 extension.json+图标文件夹，CI 自动校验+维护者审，应用内画廊拉清单 | **GitHub 仓库即索引+PR+CI+应用内拉取**——同产品形态的官方模式 |
| Raycast Store | npm 超集 manifest；PR 到 monorepo；本地 ray 先 validate；Store 指南审查 | "先本地校验再提 PR"+上架清单 |
| uTools | plugin.json+人工审核+关键字占用规则 | 中心化人审成本高（反面）；关键字占用→ID 冲突管理 |
| PowerToys Run 插件 | 下载 ZIP 解压到 Plugins 目录重启生效；社区合集页补发现性；`Community.*` 命名前缀 | drop-in 模式可行但发现性差；命名前缀做命名空间 |
| Obsidian | obsidian-releases 根放总索引 JSON，应用内直接拉；各自仓库+manifest（minAppVersion）；**id 全局唯一、不得太泛、发布后不可改**；纯人审积压数月至数月（社区诟病） | minAppVersion+id 永久稳定两条铁律；人审是瓶颈→纯数据包用 CI 替代 90% |
| VS Code 市场 | name+**publisher（命名空间）**+**engines.vscode（声明式兼容门禁）** | 作者前缀防同名劫持；engines 式版本门禁 |
| SchemaStore | `$schema` 头+catalog 收录→IDE 零配置自动校验 | 发布 schema 即免费获得 IDE 校验体验 |
| npm scopes | `@scope/name` 绑定账号防抢注/typosquatting | 作者前缀命名空间的标准解 |
| Scoop/GitHub Releases | manifest 声明上游版本；`releases/latest` API 比对 tag_name；资产 CDN 下载不限额 | 成熟自更新范式 |

### 5.2 推荐主路径：GitHub 仓库索引 + 应用内拉取（CmdPal/Obsidian 合体）

```
FancyText/styles-registry（新公开仓库）
├── index.json        ← 唯一索引（id/name/version/schemaVersion/author/description/
│                        tags/downloadUrl/sha256/official/featured）
├── packs/*.json      ← 小包直接进仓库（raw 直链即下载）
├── schema/fancytext-style-1.json
├── CONTRIBUTING.md
└── .github/workflows/validate.yml   ← CI：schema/2MB/深度/重复 ID 校验
```

应用端：设置页"获取更多包"→ 拉 `raw.githubusercontent.com` 索引（jsDelivr 镜像应对国内）→ 列表展示 → 下载 → 本地校验（schema/2MB/sha256）→ 写入 styles 目录（同包名覆盖=升级，现有机制零改动）。成本：registry+CI 约 1–2 人日，应用端 3–5 人日；MVP 可先不做 sha256 与静默更新。

三模式定位：A 仓库索引=**主路径**；B GitHub Release 附件=大文件补充；C 手动下载放入目录=**必须保留的兜底**（离线尊严）。更新：打开获取页时比对 index 与本地 version 提示升级。

### 5.3 社区规范要点

- Schema：JSON Schema 2020-12 双地址发布（官网+raw），包首行 `"$schema"` → IDE 自动校验；起量后提 SchemaStore
- **命名空间（最关键）**：包名强制"作者前缀.包名"两段式，官方保留 `fancytext.` 前缀——把"同包名覆盖=升级"的劫持面从全局收敛到作者内；ID 全局唯一/不过泛/发布后不可改；审核目检 typosquatting
- CI 机器审（schema/尺寸/深度/条目上限/ID 冲突/控制字符）+单维护者人审内容；信任作者 auto-merge 白名单
- schemaVersion 演进：读取方忽略未知字段；新增字段可选+默认；永不原地改名/删除；破坏性变更才 +1；旧应用遇高版本明确拒绝提示升级（engines 门禁模式）；index 可带 minAppVersion 反向门禁
- 官方包运营：仅 1 个核心包随程序内嵌（=plum `:preset`），其余官方包全走 registry `official:true`——避免程序体积随包数膨胀、官方社区同一路径升级；`featured` 精选位+README 精选表
- CONTRIBUTING：结构示例+$schema 自检+提 PR 步骤+元数据风格（描述短、句号结尾、禁 emoji）+license 必填（推荐 CC0/MIT）

### 5.4 风险与边界（纯数据包安全声明）

①解析器 DoS：深嵌套 JSON 可致栈溢出（真实案例：50KB 深嵌套拖垮 Visa 预订系统；RFC 8259 §9 明确允许限深度）→ 2MB 之外加深度上限（32/64）+数组长度上限；②欺骗性字符：花式文字工具天然产同形字（homoglyph 攻击原料）→ 内容红线写贡献指南（禁仿冒品牌/身份核验/钓鱼包）；包名剥离控制字符与 RTL 覆盖符 U+202E；③UI 注入：name/description 富文本上下文须转义+超长截断；④覆盖劫持：索引混入热门包同名条目即投毒→命名空间+sha256+记录来源 origin，不同来源同名覆盖要求显式确认；⑤渠道：仅 HTTPS，raw 锁 commit/tag（jsDelivr @version 不可变）；⑥法律：商标性内容风险，license 必填+官方声明"包内容归属各自作者"。对外声明一句话：声明式纯数据、不含可执行代码、不发起网络请求、导入仅写 styles 目录——风险面收敛为内容本身，配套三类防御。

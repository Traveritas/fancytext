# UI 框架选型调研（2026-09-12）

> 结论：**保持 WPF + 针对性内存优化，不迁移。**
> 背景：桌面版现用 WPF（纯代码 UI），实测常驻 ~117MB / 唤出渲染后 ~146MB；硬性理念"占用少、轻量化"。
> 本文档为调研存档，详细数据与来源见文末链接（由调研子智能体核证）。

## 核心判断

1. **WinUI 3 不省内存反而可能更重**：同形态最直接对照是微软自家的 Command Palette（WinUI 3 托盘+热键弹窗）——启动 ~100MB，社区有 726MB 空闲与多起 GB 级泄漏报告；第三方 2026 实测 WinUI 3 空闲 ~155MB vs WPF ~185MB（中型应用），而本项目 WPF 实测 117MB 已低于 WinUI 3 典型水位。
2. **托盘/热键/无边框弹窗在 WinUI 3 全要互操作补丁**（无内置 NotifyIcon、热键照旧 P/Invoke、圆角同样要 DwmSetWindowAttribute），现有互操作存量迁移即作废。
3. 文本整形（DirectWrite 级联回退）是 WinUI 3 唯一理论优势，但 126 样式已在 WPF 上渲染验证通过，换"理论更好"风险不对称。
4. 其余选项（MAUI/Avalonia/Flutter/Tauri）基线 60–400MB，均不符合轻量理念；原生 Win32 可 <20MB 但等于全部重写（2–3 个月起）。

## 优化路线（按性价比，预期常驻观感压到 20–40MB）

1. 隐藏窗口后延迟 1–2s 调 EmptyWorkingSet 修剪工作集（117MB → ~10–25MB 观感；PowerToys 官方 "low memory mode" 同思路）；
2. 隐藏时释放列表渲染资源 + LOH 压缩；
3. runtimeconfig 设 GCHeapHardLimit 封顶托管堆（保持 Workstation GC，勿开 Server GC）；
4. WinForms NotifyIcon → P/Invoke Shell_NotifyIcon（省 3–8MB，去一个程序集）；
5. GlyphTypeface/FontFamily 单例缓存。

## 禁区

PublishTrimmed（WPF 直接 NETSDK1168 报错）、NativeAOT（不支持）、ReadyToRun（增大体积，与 270KB 单文件冲突）。

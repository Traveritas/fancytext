合体候选（当前方向：B 主体 + A 页脚）

两稿只差筛选入口：E 用「全部 ▾」下拉 + ⭐🕘 图标按钮（chrome 最少，更贴 Raycast）；F 用左侧 56px 图标分类栏（分类直达，icon 集固定 9 个，样式包引入不了新分类、无需维护）。两稿的过滤都是真实可点的。

E · B+A 下拉筛选 候选

输入行右侧「全部 ▾」真实下拉（七项分类过滤、计数联动）+ ⭐🕘 快捷图标按钮；底部 A 的 keycap 栏（↑↓ 浏览 / Enter 复制 / Ctrl+D 收藏 / Esc 隐藏）。chrome 最少，视觉最干净。

F · B+A+左侧分类栏 候选

输入行只剩放大镜；左缘 56px 图标分类栏（9 项固定：全部/收藏/最近/特效/花体/装饰/变换/中文/编码），点击真实过滤。分类一步到位，重度使用更顺手。

原始四方向（存档）

A · Fluent 标准款 稳妥

微软 WinUI 3 原生风：填充式输入框（聚焦露强调色底线）、subtle-fill 胶囊、40px 行 + 左侧强调竖条。与现有代码结构最近，实现成本最低，和 Win11 融为一体。

B · Raycast 极简款 颜值

内容绝对主角：无边框大输入、17px 大预览、chrome 只剩一条分隔线一行小字；灰阶铺底，紫色只落在光标与选中处。筛选改成「全部 ▾」+ 图标按钮，交互要重做。

C · 卡片画廊款 浏览感

花式文字是视觉驱动的场景：2 列卡片网格，大预览居中、名称与分类 tag 置底，hover 轻浮起。挑装饰类样式最直观；WPF 侧需把 ListBox 换成网格虚拟化，成本最高。

D · 紧凑双栏款 效率

Listary 式键盘流：左侧 56px 图标分类栏直达、32px 高密度行、选中行下展开码点详情条。信息密度最高，重度用户友好；新增左栏与详情结构，成本中高。

方向气质信息密度WPF 实现成本适合的用法
A · Fluent 标准规范、原生、不炫技中低（沿用现有结构，换皮+补过渡）默认首选；和各种桌面环境都不违和
B · Raycast 极简安静、克制、内容主角低中（筛选交互需重设计）重输入轻浏览；追求「好看」优先
C · 卡片画廊浏览感、发现感低-中高（网格虚拟化 + 模板重做）慢慢挑样式；装饰/特效类最出彩
D · 紧凑双栏效率工具、密度高高中-高（左栏 + 详情条为新结构）高频键盘用户；分类直达

四个方向不是互斥的全部——布局、输入区、选中态都可以跨方向组合（例如 A 的骨架 + B 的输入区）。选定方向或组合后，再按 WPF 实现映射（CSS 变量 → Theme 笔刷，transition → Opacity/Transform 动画）。
